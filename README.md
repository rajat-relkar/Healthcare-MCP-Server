# Patient DB — Custom MCP Server

An [MCP](https://modelcontextprotocol.io) server that lets an AI assistant query a SQLite
healthcare database. The assistant can look up patients, summarise their risk, find hospital
readmissions and run read-only SQL — and it can never change the data.

> **All data is synthetic** (randomly generated by `seed_data.py`). Don't point this at real
> patient records without proper access control, auditing and a compliant LLM setup.

```
 You ──prompt──▶ AI agent app (MCP client) ──▶ LLM
                      │  List All Tools / Call Tool
                      │  over stdio | Streamable HTTP | SSE (deprecated)
                      ▼
                 MCP server (server.py)
                      │  tools/  ──▶  db.py  ──▶  patients.db (read-only)
```

## Project layout

| File | Purpose |
|---|---|
| `server.py` | Entry point. Creates the MCP server, registers tools, picks the transport. |
| `db.py` | The only place that opens SQLite — always **read-only**. |
| `seed_data.py` | Creates `patients.db` (5 tables) with synthetic data. The only code that writes. |
| `tools/schema_tool.py` | `get_database_schema` |
| `tools/query_tool.py` | `search_patients`, `query_patient_details`, `run_sql_query` |
| `tools/risk_summary.py` | `get_patient_risk_summary` |
| `tools/readmission.py` | `get_readmission_analysis` |
| `client/index.html` | A browser MCP client: connect, pick a tool, fill in its arguments, see the result. No LLM. |
| `documentation/` | This file, `MCP_Documentation.md` (concepts), `CORS_Explained.md` (why the browser client needs CORS), `Implementation_Plan.txt` |

## Setup

Requires Python 3.10+ (and Node.js only if you want the MCP Inspector).

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python seed_data.py          # creates patients.db (60 patients)
python server.py             # starts the server on stdio
```

`requirements.txt` pins `mcp[cli]>=2,<3`. In MCP SDK v2 the server class is `MCPServer`
(it was `FastMCP` in v1, which many older tutorials still show).

## Tools

| Tool | What it does |
|---|---|
| `get_database_schema` | Lists tables, columns and row counts so the LLM knows what exists. |
| `search_patients(name)` | Finds a `patient_id` from part of a first/last name. |
| `query_patient_details(patient_id)` | Demographics, recent visits, diagnoses, active medications, latest labs (flagged LOW/HIGH). |
| `get_patient_risk_summary(patient_id)` | Rule-based risk score (Low/Moderate/High) with points per factor. *Demo thresholds — not clinical.* |
| `get_readmission_analysis(patient_id?, window_days=30)` | Emergency/inpatient visits within N days of an inpatient discharge, plus the readmission rate. |
| `run_sql_query(sql)` | Read-only `SELECT` for custom questions; capped at 100 rows. |

## Connect a client

### Claude Desktop (stdio)

Claude Desktop starts `server.py` itself and talks to it over stdin/stdout, so you do **not** run
`python server.py` in a terminal.

1. **Seed the database** if `patients.db` doesn't exist yet:

   ```powershell
   cd C:\Users\Rajat\Desktop\Custom_MCP_Server_Patient_DB
   .venv\Scripts\python.exe seed_data.py
   ```

2. **Open the config file.** In Claude Desktop go to **Settings → Developer → Edit Config**. The
   file is `claude_desktop_config.json`, and its location depends on how Claude was installed:

   | Install | Path |
   |---|---|
   | Microsoft Store | `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\claude_desktop_config.json` |
   | Installer (.exe) | `%APPDATA%\Claude\claude_desktop_config.json` |

3. **Add the server** under `mcpServers`. If the file already has an `mcpServers` block, add
   `patient-db` next to the existing entries — don't create a second `mcpServers` key.

   ```json
   {
     "mcpServers": {
       "patient-db": {
         "command": "C:\\Users\\Rajat\\Desktop\\Custom_MCP_Server_Patient_DB\\.venv\\Scripts\\python.exe",
         "args": ["C:\\Users\\Rajat\\Desktop\\Custom_MCP_Server_Patient_DB\\server.py"]
       }
     }
   }
   ```

   - `command` must be the **venv's** `python.exe`: that is the Python with `mcp` installed. A bare
     `python` may resolve to a different interpreter and fail with `No module named mcp`.
   - Use absolute paths and double the backslashes (`\\`), as JSON requires.

4. **Fully quit and reopen Claude Desktop.** Closing the window isn't enough; quit it from the
   system tray. The config is only read at startup.

5. **Check it connected.** Open a new chat and click the tools icon near the input box (or
   **Settings → Developer**): **patient-db** should be listed as running, with six tools:
   `get_database_schema`, `search_patients`, `query_patient_details`, `get_patient_risk_summary`,
   `get_readmission_analysis` and `run_sql_query`.

6. **Try a prompt**, e.g. *"Use patient-db to show me the database schema, then find patients named
   Sharma."* Claude asks permission the first time it uses each tool; choose **Allow** (once or always).

If the server doesn't appear, see [Troubleshooting](#troubleshooting).

### Claude Code

```powershell
claude mcp add patient-db -- C:\Users\Rajat\Desktop\Custom_MCP_Server_Patient_DB\.venv\Scripts\python.exe C:\Users\Rajat\Desktop\Custom_MCP_Server_Patient_DB\server.py
```

### Remote / HTTP

```powershell
python server.py --transport streamable-http --port 8000     # endpoint: http://127.0.0.1:8000/mcp
claude mcp add --transport http patient-db http://127.0.0.1:8000/mcp
```

### Browser client

`client/index.html` needs two terminals:

```powershell
# 1. the MCP server, allowing this one web page origin to call it
python server.py --transport streamable-http --cors-origin http://localhost:3000

# 2. a tiny static web server for the page
python -m http.server 3000 --directory client
```

Open **http://localhost:3000**, click **Connect**, choose a tool, fill in the arguments and click
**Run tool**. Results show as tables, JSON or the raw MCP message, and the *Protocol log* at the
bottom shows every request and response (`initialize`, `tools/list`, `tools/call`, ...).

- Open it via `http://localhost:3000`, **not** by double-clicking the file: a `file://` page has
  the origin `null`, which the server refuses.
- `http://localhost:3000` and `http://127.0.0.1:3000` are different origins. Pass the one you use
  (`--cors-origin` can be repeated).
- Wildcards (`*`) are rejected on purpose: they would let any website you visit read patient data
  from this server.
- This client does not use an LLM, so it needs no API key.

## Troubleshooting

- **Tool says only `Error executing tool ...`** — an unexpected crash; the details are in the
  server's log (stderr). Errors the server anticipates (unknown patient, bad SQL) include a message.
- **`Database not found`** — run `python seed_data.py`, or set `PATIENT_DB_PATH` to your `.db` file.
- **Client can't start the server** — use the absolute path of the Python that has `mcp` installed.
- **Claude Desktop doesn't list `patient-db`** — check that the JSON is valid (a trailing comma or a
  single `\` in a path breaks the whole file), that you fully quit and reopened the app, and read
  `mcp.log` in the `logs` folder next to `claude_desktop_config.json`.
- **Browser client says "Can't reach the server"** — either the server isn't running, or the browser
  blocked the request (CORS). Both look the same to JavaScript. Start the server with
  `--cors-origin` set to the exact address in the browser's address bar (the banner prints the
  command for you).
- **Browser client says "Session expired"** — the server was restarted. Click Connect again.
- **Never `print()` in stdio mode** — stdout carries the protocol. Log to stderr instead.

## Using your own database

Point `PATIENT_DB_PATH` at your file. `run_sql_query` and `get_database_schema` work with any
schema; `query_patient_details`, `get_patient_risk_summary` and `get_readmission_analysis`
assume the five tables and column names created in `seed_data.py`.
